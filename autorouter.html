How Auto Router works, step by step

  1. 1
    You send a message. The page sends your prompt and recent conversation to a Cloudflare Worker on this website.
  2. 2
    The Worker calls AI Gateway. It validates the request, applies a per-visitor rate limit, and asks for cloudflare/auto rather than a specific model. Credentials stay on Cloudflare.
  3. 3
    The gateway checks the model pool. Only our allowed Workers AI models are considered. Unsupported inputs, unavailable providers, and account or spending restrictions can make a model ineligible.
  4. 4
    Auto Router evaluates the task. It classifies the conversation's task and difficulty, then ranks eligible models by expected response quality and cost.
  5. 5
    A model generates the answer. The gateway tries the top-ranked candidate and can fall back to another eligible model if it cannot serve the request. This demo requests a fresh routing decision for every message.
  6. 6
    You see the reply; we see the request. The Worker returns the answer and routing details to the chat. AI Gateway records the prompt and response for inspection in the dashboard. Response caching is skipped in this demo.

Why use Auto Router?

It's not just cost control. The goal is to balance expected answer quality and cost for each task, rather than always using the cheapest model or always paying for the most capable one.

Match the model to the task

A quick explanation and a difficult coding problem may need different capabilities. Auto Router estimates the task's difficulty and chooses a suitable model from the eligible pool. These are predictions, not fixed rules or guarantees of answer quality.

Avoid unnecessary model spend

When a lower-cost model is expected to handle a task well, using a more expensive model may add little value. Routing considers that tradeoff. Separate gateway rate limits and spending budgets provide additional controls; Auto Router itself is not a hard budget cap.

Keep requests moving

The gateway excludes unhealthy providers and can try another eligible model if the selected candidate cannot serve the request. This improves resilience, but requests can still fail if no suitable candidate is available.

Simplify your application

Your app asks for cloudflare/auto instead of maintaining its own model-selection logic. You still control which models and providers are allowed. In this demo, every request stays within our three-model Workers AI pool.

How does Cloudflare decide?

First, it filters for models that can accept the request and are available under your credentials, billing configuration, and spend limits. Then it analyzes the conversation's task type and difficulty, scores the eligible models by expected quality versus cost, and tries the top-ranked candidate. If that candidate cannot serve the request, it can try the next one.

The public documentation explains this process, but does not publish the exact scoring formula. It is not random selection, round robin, or a promise to pick the cheapest model. The routing reason shown beneath each reply helps explain what happened; evaluate the answers and gateway logs against your own application's needs.
