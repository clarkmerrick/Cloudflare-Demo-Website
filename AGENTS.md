# Project conventions

- This is a static Bootstrap website. Reuse the theme classes in `assets/dist/css/bootstrap.min.css` and plain browser JavaScript; no npm install or build step is required.
- Assistant replies use pinned Marked and DOMPurify browser scripts with SHA-384 integrity checks. Sanitize parsed Markdown with the chat's HTML/attribute allowlist; keep user messages and metadata as plain text, exclude remote images, and retain a plain-text fallback if either library is unavailable.
- Run `node --test tests/*.test.mjs`, `node --check assets/autorouter.js`, `node --check assets/autorouter-stats.js`, `node --check workers/ai-chat.mjs`, and `git diff --check` before publishing chat changes.
- For Markdown UI checks, start `python3 -m http.server 8765 --bind 127.0.0.1`, then run `npm exec --yes --package=@playwright/test@1.56.1 -- node tests/chat-markdown.browser.mjs`. The browser test mocks inference requests, checks sanitization and mobile layout, and can target the live page by appending `https://demo.clarkmerrick.com/autorouter`. On non-macOS systems, use an installed Playwright Chromium or set `BROWSER_EXECUTABLE`.
- Cloudflare Pages project `demo-clarkmerrick-com` builds `main` from GitHub repository ID `630177371`. Cloudflare displays its historical name `clarkdemo.com`; the current GitHub name is `clarkmerrick/Cloudflare-Demo-Website`.
- The public site is `https://demo.clarkmerrick.com`. Its delegated zone ID is `df194a551022ee768d93a48d2aff4647`, not the parent `clarkmerrick.com` zone.
- The Auto Router page is `/autorouter`. Its same-origin POST endpoint `/api/ai-chat` and GET endpoint `/api/ai-stats` are separate Worker routes, not Pages Functions. Local static servers and the Pages hostname do not have these routes.
- Worker source is `workers/ai-chat.mjs`; its deploy configuration is `.devin/wrangler.jsonc`. Deploy using `wrangler deploy --config .devin/wrangler.jsonc` with an authenticated Wrangler installation, or the Cloudflare MCP. GitHub pushes automatically publish the static pages, but do not redeploy this separate Worker.
- AI Gateway `demo-auto-router` requires authentication, collects prompt/response logs, skips response caching, and bills Workers AI postpaid. Every inference must call `cloudflare/auto` through the AI binding, with the Workers AI provider and all seven currently documented Auto Router-supported Workers AI chat candidates fixed server-side. This is not the full Workers AI image/audio/text catalog; check the public Auto Router docs when updating this pool. Do not introduce a direct-model fallback.
- Cloudflare gateway limits are 20 requests per 60 seconds and a $5 rolling 24-hour estimated spend budget. The Worker limits each IP to approximately 6 requests per minute per Cloudflare location, bounds encoded request bodies to 1,000,000 bytes, individual messages to 200,000 characters, and conversation context to 240,000 characters. Frontend and Worker limits must stay synchronized. Do not add a textarea maxlength: preserve oversized pastes and show an explicit validation warning. Only older context may be dropped, never the latest message. Spend limits are eventually consistent, not a guaranteed hard billing cap.
- Public aggregate statistics are served by GET `/api/ai-stats` from the same Worker, cached for 60 seconds. D1 database `demo-auto-router-usage` stores only hourly model counts in `model_usage`; its schema is `.devin/usage-schema.sql`. Do not store or expose prompts, responses, session IDs, IP addresses, or credentials through this statistics store or endpoint.
- Statistics cover 24 UTC hourly buckets including the current partial hour. The `live` source is incremented by the Worker after inference attempts; `gateway-import` counts can be seeded idempotently from older gateway logs, excluding logs marked `metadata.usage_tracking: v1` to prevent double counting. Test/demo traffic is included and unreported upstream errors have their own bucket.
- Run `npm exec --yes --package=@playwright/test@1.56.1 -- node tests/chat-stats.browser.mjs` against the local server to check chart rendering, percentages, empty/error states, and mobile layout. Both browser test scripts mock inference/statistics as needed and do not create real AI usage.
- Inference output is bounded to 4,096 tokens, including reasoning tokens. A lower limit can cause complex prompts to return an empty answer with `finish_reason: length`.
- Each page load and New chat creates a random UUID session ID held only in memory. The Worker validates it, records it in `metadata.session_id`, and forwards `cf-aig-session-id` alongside `cf-aig-no-session-affinity: true`. Session tracking must not pin models, track visitor identity, or use browser storage. Requests from older clients without a session ID receive a generated per-request ID.
- Chat requests carry a UUID `X-Request-ID`, echoed as `requestId` and `X-Request-ID` in responses and recorded as `request_id` in private Worker events and AI Gateway metadata. The UI shows a reference ID even for network failures. These IDs are correlation labels, not authentication. The Worker inference deadline is 120 seconds; the browser deadline is 130 seconds.
- Worker observability must stay enabled with persistent custom logs at 100% sampling and `redact_query_string: true`. Keep `logs.invocation_logs: false`: automatic HTTP invocation snapshots include request headers, whereas the custom events provide the required timings/correlation without those snapshots. Events are `chat.started`, `chat.completed`, `chat.failed`, `chat.metrics_failed`, and `stats.failed`. Log only identifiers, stages, durations, input/output sizes, model/routing fields, safe numeric error codes, and allowlisted error names/network codes. Never log raw prompts, replies, request headers, exception messages/stacks, or provider error bodies. None of these diagnostic records belong in the public statistics database or endpoint.
- To investigate a reference ID through `cloudflare-api`, discover the Observability API schema with `search`, then POST `/accounts/{account_id}/workers/observability/telemetry/query` using `view: events`, `dry: true`, an ad-hoc `queryId`, a narrow millisecond `timeframe`, and `parameters` containing `datasets: []`, a string equality filter on `$metadata.service` for `demo-auto-router-chat`, and `needle: { value: REFERENCE_ID, matchCase: false }`. This full-text query works without assuming custom field prefixes. Use `/workers/observability/telemetry/keys` before building field-specific filters. Gateway logs can be searched with the same reference ID because it is stored in `metadata.request_id`. Query promptly within Cloudflare's log-retention window; old failures without recorded diagnostics cannot be reconstructed reliably.
- MCP verification confirmed the custom filter key is `request_id` (string); returned records store custom fields in `result.events.events[].source`. For an exact lookup, combine a `$metadata.service` equality filter with `request_id` equality. The platform's `$metadata.requestId` is a separate invocation ID, not the reference shown to visitors. Never publish real diagnostic records or reference/session IDs in this repository.
- The deployed public Worker routes match exact URLs. Adding a query string to `/api/ai-chat` can fall through to Pages and return an empty 405 response; use the `X-Request-ID` header, not a query parameter, for live diagnostic probes.
- Error codes distinguish `inference_timeout` (app deadline), `upstream_timeout` (HTTP 408/504), `upstream_aborted`, `upstream_unavailable`, `upstream_error`, `upstream_rejected`, `invalid_upstream_response`, `output_limit`, `empty_response`, and local validation/rate-limit failures. Do not assume every generic failure was a timeout or bypass Auto Router with a direct-model fallback.
- Do not add API tokens to browser code or committed files. Public prompt logging must remain disclosed on the page. Do not copy internal wiki content, private source code, or unpublished routing details into this public repository.
